Checkpoint 00 · Foundation

Chuẩn bị môi trường

Tạo nền tảng ổn định trước khi bắt đầu triển khai service.

Vấn đề

Mỗi máy có thể khác Python, thư viện và cấu hình. Thiếu dependency hoặc cấu hình sai khiến ứng dụng không chạy ngay từ đầu.

Tôi xử lý như thế nào
  • Tạo repository cá nhân đúng tên và cài dependency trong môi trường ảo Python.
  • Tạo .env từ .env.example; giữ API key ngoài Git.
  • Khởi động Redis hoặc dùng Redis giả để bắt đầu khi chưa có Docker.
Kết quả

Môi trường sẵn sàng chạy ứng dụng và kiểm tra từng checkpoint. Test chức năng còn lỗi trước khi viết code là điều dự kiến; mục tiêu CP0 là pytest chạy được và báo lỗi rõ ràng.

Checkpoint 01 · Configuration & observability

Cấu hình, health & logging

Tách cấu hình khỏi code và giúp service dễ chẩn đoán khi chạy trên cloud.

Vấn đề

Hardcode secret gây rủi ro khi deploy. Log print() khó lọc; health check phụ thuộc Redis có thể khiến service bị restart khi Redis chỉ tạm lỗi.

Tôi xử lý như thế nào
  • Đọc cấu hình từ biến môi trường theo nguyên tắc 12-Factor.
  • Bắt buộc có AGENT_API_KEY để phát hiện thiếu secret ngay lúc khởi động.
  • Ghi log theo từng dòng JSON; dùng /health kiểm tra process mà không gọi Redis.
Kết quả

Cùng một phiên bản ứng dụng chạy được ở nhiều môi trường bằng cách đổi cấu hình; liveness check không kéo theo dependency ngoài.

Checkpoint 02 · Containerization

Đóng gói bằng Docker

Đưa ứng dụng và môi trường chạy vào một image nhất quán giữa local và server.

Vấn đề

Ứng dụng chạy trên máy cá nhân chưa chắc chạy trên server. Image lớn làm deploy chậm; chạy bằng root hoặc đưa .env vào build context tạo thêm rủi ro.

Tôi xử lý như thế nào
  • Dùng multi-stage build để không mang công cụ build vào image runtime.
  • Chạy bằng user thường; đọc cổng từ $PORT và thêm healthcheck.
  • Bổ sung .dockerignore; dùng Compose chạy agent và Redis qua hostname service.
Kết quả

Ứng dụng được đóng gói cùng môi trường cần thiết, sẵn sàng chạy local và làm nền cho cloud deployment.

Checkpoint 03 · API security

Bảo vệ API & chi phí

Giới hạn quyền truy cập và kiểm soát mức sử dụng trước khi gọi LLM.

Vấn đề

API công khai có thể bị gọi trái phép hoặc lạm dụng, làm tăng chi phí LLM. Rate limit đơn lẻ không giới hạn được tổng chi tiêu.

Tôi xử lý như thế nào
  • Yêu cầu API key và so sánh bằng compare_digest.
  • Dùng sliding-window rate limit theo từng người dùng.
  • Theo dõi ngân sách tháng; kiểm tra xác thực, tốc độ và ngân sách trước lời gọi LLM.
Kết quả

Request bị chặn trước khi gọi LLM; API phân biệt lỗi xác thực 401, vượt tốc độ 429 và vượt ngân sách 402.

Checkpoint 04 · Reliability

Scale & độ tin cậy

Giữ service nhất quán khi chạy nhiều instance hoặc khi một instance cần dừng.

Vấn đề

Lịch sử trong RAM không được chia sẻ giữa các instance. Khi deploy hoặc Redis gặp sự cố, health check cần phân biệt process còn sống với service sẵn sàng nhận traffic.

Tôi xử lý như thế nào
  • Lưu lịch sử hội thoại trong Redis, giới hạn số message và đặt TTL.
  • Dùng /health cho liveness và /ready kiểm tra Redis/readiness.
  • Xử lý SIGTERM/SIGINT để báo shutdown và chuyển tiếp handler cũ.
Kết quả

Các instance chia sẻ lịch sử; load balancer có thể ngừng gửi traffic tới instance chưa sẵn sàng trong lúc khởi động hoặc shutdown.

Checkpoint 05 · Cloud deployment

Triển khai lên cloud

Đưa service lên Render và xác minh API công khai hoạt động đúng.

Vấn đề hiện tại

URL Render đã có và /health trả 200, nhưng /ready và /ask đang trả 500. Tài liệu hiện tại chưa xác nhận nguyên nhân.

Tôi xử lý như thế nào
  • Kiểm tra biến môi trường trên Render, nhất là REDIS_URL và cấu hình API key.
  • Đọc runtime log để tìm nguyên nhân 500 trước khi sửa; không đưa secret vào repository.
  • Sau khi cập nhật và redeploy, kiểm tra lại health, readiness và /ask có/không có key.
Hiện trạng

Service đang hoạt động một phần. Chỉ đánh dấu CP5 hoàn tất sau khi xác minh được nguyên nhân và kiểm tra lại các endpoint.

Checkpoint 06 · Bonus CI/CD

CI/CD tự động

Tự động kiểm tra thay đổi trước khi deploy và lưu lại dấu vết của mỗi lần phát hành.

Vấn đề

Deploy thủ công dễ bỏ qua test, khó biết commit nào đang chạy và có thể gặp lỗi chỉ xuất hiện khi build trên môi trường sạch.

Tôi xử lý như thế nào
  • Dùng GitHub Actions chạy test và build Docker image trên runner sạch.
  • Chỉ deploy khi test và build thành công; giới hạn deploy ở push lên main.
  • Lưu deploy hook trong GitHub Secrets và gọi smoke test /health sau deploy.
Kết quả

Workflow CI/CD đã có trong repository; cần kiểm tra trạng thái chạy thực tế trước khi kết luận pipeline đang xanh.
